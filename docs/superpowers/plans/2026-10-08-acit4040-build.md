# ACIT4040 AI Interior Design Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the complete modular ACIT4040 interior-design system from an empty repository, with an executable demo path and replaceable production ML/data adapters.

**Architecture:** A React/Vite frontend talks to a modular FastAPI backend. Domain services own preference learning, furniture retrieval, compatibility and layout; PostgreSQL owns application state and Qdrant owns vectors. Dataset/model managers use manifests and versioned artifacts so setup is idempotent. An orchestration agent sits above tested deterministic services rather than replacing them.

**Tech Stack:** React, TypeScript, Vite, React Three Fiber, Three.js, Python, FastAPI, Pydantic, SQLAlchemy, PostgreSQL, Qdrant, PyTorch/Hugging Face adapters, pytest, Ruff, mypy, ESLint, Vitest, Docker Compose, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-08-acit4040-ai-interior-design.md`; source requirements: `ACIT4040_build_from_scratch_specification.md`.

## Global Constraints

- "reuse existing data first, download only what is missing, preprocess only what is necessary, and make every setup step idempotent."
- "Do not make the image generator the source of truth for furniture"
- "Five should be the initial round."
- "70% likely-preference candidates" and "30% exploratory candidates" are initial adaptive-selection defaults.
- "Do not force users through unnecessary rounds."
- "Use Qdrant for vector retrieval."
- "Start with deterministic constraints."
- "Do not add an autonomous agent before this works."
- "CI must not download the complete research datasets."
- "Do not store large binary datasets directly in PostgreSQL."
- "Do not bake large datasets into application Docker images."
- "Build vertically, not horizontally."

## Agent Handoff Protocol

Every implementation agent must leave a concise, machine-readable handoff for the next agent. The handoff is persistent project context, not conversational memory. The controller must pass the relevant handoff report path into the next task dispatch.

Each task report must record:

1. **What was implemented**: files, interfaces, and behavior that now exist.
2. **What was learned**: important repository conventions, dependency behavior, test discoveries, or integration details that the next agent would otherwise have to rediscover.
3. **Decisions and rationale**: non-obvious choices and why they were made.
4. **Interfaces for downstream tasks**: exact exported APIs, schemas, environment variables, database/vector assumptions, and compatibility constraints that later tasks consume.
5. **Tests and verification**: commands run and their results.
6. **Known limitations or concerns**: unresolved issues, deferred improvements, or assumptions that later agents must respect.
7. **Next-agent instructions**: concrete context required to safely continue, without copying the entire previous task history.

The subagent-driven workflow also maintains a progress ledger. The ledger records task completion, rulings, review findings, and fix rounds. Task reports contain the detailed technical handoff; the ledger contains the durable execution state and decisions.

A later agent must read its own task brief first, then the explicitly referenced prior handoff reports and ledger entries relevant to the interfaces it touches. Agents must not infer missing context from the conversation history.

## Review Focus

- Missing/corrupt dataset artifacts must produce an actionable status instead of silently succeeding. Covered by dataset-manager tests.
- A preference round with fewer than five usable candidates must fail clearly rather than fabricate candidates. Covered by preference API tests.
- Unknown furniture metadata must remain unknown rather than being invented. Covered by furniture validation tests.
- Invalid layouts must identify collision/boundary/door/path violations deterministically. Covered by layout validator tests.
- Frontend/API connectivity failures must expose actionable retry states. Covered by frontend service tests and E2E.
